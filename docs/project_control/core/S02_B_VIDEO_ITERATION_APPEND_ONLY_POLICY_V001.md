**Product Owner 决策（2026-10-18）：**「不要替换版本，就是每个被审批的版本作为一次有效迭代加入main，而不是有v018了，就不要v006了」。

## 已锁定的版本管理原则

1. **版本累积，不覆盖。** 每个 Product Owner 批准的完整视频，是该版本下独立、有效且可回看的一次生产迭代。**新版本不是旧版替身**，不得因为 V018 出现而删除、重命名、覆盖或撤销 V006 等历史素材。
2. **批准状态必须精确。** 已视觉批准 ≠ 已正式发布 ≠ 通过所有人像保护 GT ≠ 允许替换主剪辑母版。未经 PO 明确视频批准的版本，不可伪称 `APPROVED`。
3. **主分支作累计档案。** 凡完成 PO 视频视觉审批的迭代，保留确切二进制（SHA-256）、版本号、源版本、配置、审批日期及审批范围，**新增**到 `main` 并在独立版本账本追加条目；已有批准条目不得删除或指向其他二进制。
4. **需要的中间来源保留。** 未获批准但作为后续迭代明确基底的视频（如 S02-B V006 重构审片版）应保留为 `REFERENCE_BASELINE / PO_REVIEW_PENDING`，以保证 V018 可追溯；这不代表其本身已经获 PO 审批。
5. **M01 不覆盖剪辑。** `S02_B_V006_CINEMATIC_ROUGH_RECONSTRUCTED_CANDIDATE_V001.mp4` 是后续 V018 特效效果的明确参考源；V018 是视觉已批准的烛火处理版本，不得令 V006 失效。二者各自独立存档并可同时比较。
6. **绝不静默“替换当前版”。** UI 可以单独有 `latest_approved` 指针以便快速访问，但是只能新增或更新指针，不得覆盖任何旧版本文件或其记录。图像/母版正式发布、删除成果及历史改写另须 PO 单独授权。
7. **发布可追溯**：内容清单须列 Git 路径、精确 SHA-256、版本之间的 `derived_from`、`approval_scope`、技术 QC 与 Project Control 决策记录。二进制不得借“发布”而重新编码。
8. **治理一次定义，长期适用。** 今后所有 S02-B 有效视频迭代按此原则执行；不得因新迭代覆盖旧审批记录，也不得自动把未批准的候选批量并入已批准索引。
